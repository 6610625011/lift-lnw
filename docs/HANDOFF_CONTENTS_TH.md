3. [ภาพแดชบอร์ดจากการทดสอบ](images/dashboard-live.png): ภาพเก่าเพื่อประกอบการนำเสนอ ไม่ใช่ข้อมูลสดหรือหลักฐานว่าปัญหา Wi-Fi หายแล้ว

## ภายใน ZIP มีอะไร

| โฟลเดอร์/ไฟล์ | สิ่งที่อยู่ข้างใน |
|---|---|
| `README.md` | จุดเริ่มต้นสำหรับทีม |
| `docs/` | คู่มือภาษาไทย เอกสาร Windows การต่อสาย และภาพประกอบ |
| `src/` และ `include/` | โค้ด ESP32 และค่าตั้งจำลอง พร้อมตัวอย่างไฟล์ตั้งค่าที่ไม่มีรหัสจริง |
| `platformio.ini` | บอร์ด `esp32dev` และรายการไลบรารี |
| `windows/node-red/` | flow, template แดชบอร์ด, Function และรายการแพ็กเกจ/lockfile |
| `windows/test-tools/` | รายการแพ็กเกจเครื่องมือทดสอบหน้าเว็บ ไม่มีตัวแพ็กเกจติดตั้ง |
| `windows/local-secrets.example.json` | ตัวอย่างช่องตั้งค่า **ต้องเปลี่ยนค่าตัวอย่างก่อนใช้งาน** |
| `scripts/` | สคริปต์เปิดระบบ สร้าง flow ตั้ง broker และตรวจการทำงาน |
| `test/` | การทดสอบแบบจำลองและเงื่อนไขฝั่งแดชบอร์ด |
| `overview/` | เอกสารโจทย์เดิมสำหรับอ้างอิง |
| `MANIFEST_SHA256.txt` | รายการไฟล์ในชุดพร้อม SHA-256 ใช้ตรวจไฟล์ |

## สิ่งที่ตั้งใจไม่ใส่ใน ZIP

ไม่มี `include/secrets.h`, `windows/local-secrets.json`, `flows_cred.json`, ไฟล์รหัสผ่านของ Mosquitto, ฐานข้อมูล broker, บันทึกดิบ, โฟลเดอร์ `node_modules`, `.pio`, ตัวติดตั้งโปรแกรม หรือไฟล์เฟิร์มแวร์ `.bin/.elf`

ไฟล์เฟิร์มแวร์ที่คอมไพล์แล้วอาจฝังรหัสผ่านไว้ด้วย จึงส่งเป็นซอร์สโค้ดและไฟล์ตัวอย่างแทน เอกสารออกแบบเก่าที่ใช้ Pi/RFID/RS-485 และวงจรรุ่นเก่าไม่ได้รวมในชุด เพื่อให้ทีมยึดสถาปัตยกรรม Windows ปัจจุบัน

## ถ้าทีมจะสาธิตด้วยเครื่องเดิม

ใช้โฟลเดอร์งานเดิมซึ่งมีโปรแกรมและค่าตั้งส่วนตัวอยู่แล้ว เปิด `Start Mockup.cmd` และแดชบอร์ดตามคู่มือ ไม่ต้องนำไฟล์ตัวอย่างไปทับค่าตั้งเดิม ตรวจข้อมูลสดก่อนสาธิตทุกครั้ง เพราะ Wi-Fi ยังขาดช่วงได้

## ถ้าทีมจะติดตั้งบนเครื่อง Windows ใหม่

ขั้นตอนนี้เป็นแนวทางเตรียมเครื่อง ไม่ใช่ผลทดสอบว่า ZIP ใช้งานได้ทันทีบนเครื่องอื่น ให้ผู้ดูแลเครื่องตั้งค่าตามสภาพเครือข่ายจริง

1. ติดตั้ง Node.js ที่รองรับ Node-RED, PlatformIO และโปรแกรม Mosquitto จากแหล่งทางการ เวอร์ชันบนเครื่องที่ทดสอบคือ Node.js 24.15.0, Node-RED 5.0.9, FlowFuse Dashboard 1.34.1 และ Mosquitto 2.1.2
2. สคริปต์ในชุดคาดว่า Mosquitto Windows binaries และ DLL ที่มากับชุดทางการอยู่ใน `windows/mosquitto/` อย่างน้อยต้องมี `mosquitto.exe` และ `mosquitto_passwd.exe` พร้อม DLL ของโปรแกรม หากติดตั้งไว้ที่อื่น ให้ปรับเส้นทางในสคริปต์ที่เรียกโปรแกรมก่อน
3. ติดตั้งแพ็กเกจ Node-RED จากรากโฟลเดอร์ที่แตก ZIP โดยใช้ `npm ci --prefix windows/node-red` ส่วน `npm ci --prefix windows/test-tools` ใช้เฉพาะเมื่อต้องการทดสอบหน้าเว็บด้วย Playwright
4. คัดลอก `windows/local-secrets.example.json` เป็น `windows/local-secrets.json` แล้วกำหนดชื่อ/รหัส Wi-Fi, IP ของ Windows ที่ ESP32 ติดต่อได้, บัญชี MQTT และค่า `credentialSecret` ที่สุ่มใหม่สำหรับเครื่องนี้ ใช้รหัสใหม่และไม่แชร์ไฟล์จริง
5. คัดลอก `include/secrets.example.h` เป็น `include/secrets.h` แล้วใส่ Wi-Fi และข้อมูล broker ให้ตรงกัน บัญชี/รหัส MQTT ต้องเหมือนใน `windows/local-secrets.json`
6. สร้างโฟลเดอร์ `windows/broker` และ `windows/logs` หากยังไม่มี จากรากโปรเจกต์รัน `node scripts/configure-broker.cjs` เพื่อสร้างไฟล์ broker ที่ใช้เส้นทางของเครื่องใหม่ และ `node scripts/generate-flows.cjs` เพื่อสร้าง flow กับบัญชี MQTT ของ Node-RED ต้องหยุด Node-RED ก่อนสร้างทับไฟล์
7. ตัวอย่างตั้งค่าใช้ `networkMode` เป็น `existing-wifi` ให้ทั้ง Windows และ ESP32 อยู่เครือข่ายที่ติดต่อกันได้ หากต้องการใช้ฮอตสปอตเหมือนเครื่องต้นแบบ เปลี่ยนเป็น `windows-hotspot`, ตั้ง `hotspotSsid`/`hotspotPassword`, ให้ ESP32 ใช้ชื่อ/รหัสชุดนั้น และตรวจที่อยู่จริงของ Windows ฝั่งฮอตสปอตก่อนตั้ง `mqttHost` โดยเครื่องเดิมใช้ `192.168.137.1`
8. อนุญาต MQTT ผ่าน Windows Firewall ให้ตรงกับเครือข่าย เครื่องต้นแบบมี `Allow MQTT WiFi.cmd` ซึ่งเปิดหน้าต่างขอสิทธิ์ผู้ดูแล และจำกัดไว้ที่โปรแกรม broker กับเครือข่ายท้องถิ่น ไม่ต้องเปิดพอร์ตออกอินเทอร์เน็ต
9. อัปโหลดโค้ดด้วย PlatformIO โดยใช้บอร์ด `esp32dev` พอร์ต USB อาจไม่ใช่ COM3 บนเครื่องใหม่
10. เปิด `Start Mockup.cmd` แล้วตรวจทั้งข้อความ `MQTT connected` ใน Serial Monitor และข้อมูลสด A–D บนแดชบอร์ด ก่อนเริ่มทดสอบเดินทาง

บางสคริปต์เกี่ยวกับฮอตสปอตใช้ API ของ Windows รุ่นใหม่ และสคริปต์ทดสอบหน้าเว็บอ้างตำแหน่ง Microsoft Edge บน Windows เครื่องใหม่อาจต้องปรับเส้นทาง/ความสามารถให้ตรงกับเครื่องนั้น สคริปต์ `prefer-2ghz.ps1` เปลี่ยนค่าการเลือกย่านของการ์ด Wi-Fi ทั้งเครื่อง ไม่ใช่ขั้นตอนบังคับของการอ่านเอกสารหรือเปิด flow และไม่ได้ยืนยันว่าจะแก้ปัญหาเครือข่ายได้ทุกเครื่อง

ไฟล์ broker ที่สร้างแล้วมีเส้นทางแบบเต็ม หากย้ายโฟลเดอร์ภายหลังควรสร้าง configuration ใหม่ ตรวจว่ารหัสผ่านที่ broker ใช้ยังตรงกันก่อนเริ่มระบบ

## สถานะผลทดสอบที่ควรอ้าง

การทดสอบแบบจำลองบนคอมและการเดินทางจริงผ่าน MQTT เคยผ่าน แต่การตรวจความต่อเนื่องภายหลังยังพบปัญหา อย่าอ้างว่า “ผ่านทุกการทดสอบ” หรือ “ระบบเสร็จสมบูรณ์” จากการมีไฟล์ทดสอบใน ZIP เพียงอย่างเดียว
